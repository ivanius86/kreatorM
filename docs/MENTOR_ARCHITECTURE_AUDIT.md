# Mentor aplikacija — READ-ONLY arhitektonski audit

Datum: 12. oktobar 2026. Referenca: [`MENTOR_FOUNDATION_BLUEPRINT_V1.md`](MENTOR_FOUNDATION_BLUEPRINT_V1.md), naročito §7, §9, §11, §13–14 i §23–25. Ovo je statički pregled postojećeg vanilla JavaScript koda. Nisu menjani programski fajlovi, podaci, storage šema ni tema. Linije su navigacioni orijentiri za trenutno stanje fajlova.

**Status nakon audita (12. oktobar 2026):** Nalazi A1 (Finance tajmer) i A3 (Nutrition favoriti) su implementaciono adresirani naknadnim izmenama. Dodati su ciljani testovi, ali nisu izvršeni jer `node`/`npm` nisu dostupni u radnom okruženju; zato runtime potvrda ostaje otvorena. A2 (Dashboard/Journal) nije rađen jer ti moduli još nisu u razvoju. Tabela ispod beleži stanje u trenutku audita.

## Summary

Aplikacija već ima realan Data Layer, Dexie/IndexedDB izbor repository-ja, migraciju sa checkpoint-ima, backup/restore i lazy loading. Glavni moduli uglavnom čitaju i pišu kroz repository/service sloj. Arhitektonski dug je koncentrisan u velikim global-script modulima, potpunom HTML rerenderovanju pojedinih prikaza i lifecycle zavisnostima od stalnih DOM čvorova. **Nije potvrđen ES-module import ciklus**: aplikacija koristi redosled klasičnih `<script>` tagova i `window.*` ugovore. **Nije potvrđen gubitak korisničkih podataka** u ovom pregledu.

Pre MVP-a treba rešiti potvrđeno pozadinsko osvežavanje finansijske imovine izvan aktivnog prikaza i zameniti prividne podatke na Dashboard/Journal MVP putanji. Ostalo raditi po malim, funkcionalno ograničenim koracima. Theme Engine, Theme Adapter i Layout Slots ostaju posle stabilizacije MVP-a, kako blueprint nalaže.

### Data Layer i integritet podataka

`js/data/index.js:4–119` prvo pravi localStorage repository-je, zatim izvršava migraciju i bira IndexedDB implementacije prema zabeleženom selection stanju. `js/data/bootstrap/data-bootstrap.js:6–24` čeka izbor i hidrira core; `feature-hydration.js:6–34` hidrira lazy feature-je. `brainstorming.js:253–263`, `finansije.js:3344–3395`, `kalendar.js:559`, `financeDashboard.js:90–98` koriste aktivne repository-je ili durable-save servis. Stari `storageService.js` i `js/nutrition/{nutrition-storage,inventory-storage}.js` i dalje čitaju/pišu legacy localStorage u kompatibilnosti/migraciji; to ne treba mehanički ukloniti. Izuzetak koji je aktivan na feature UI putanji je A3.

Backup put ima manifest, checksum i validaciju (`js/data/backup/backup-export.service.js:18–129`), IndexedDB parity (`js/data/backup/indexeddb-backup.service.js:448–475`) i transakcioni restore sa pre-action backup proverom (`js/data/recovery/indexeddb-restore.service.js:33–162`). Migracija je zasebna u `js/data/migration/legacy-to-indexeddb.service.js` (~118 KB) sa checkpoint/verifikacionim servisima. Zbog važnosti korisničkih podataka, svaki sledeći schema cutover zahteva proveru stvarnog backup/restore roundtrip-a, uključujući legacy i media blob-ove. Samo statički pregled ne dokazuje uspešan restore u browseru.

### Testovi i granice provere

`package.json` definiše `npm test` kao storage + nutrition + research; pod `tests/` je 20 `*.test.js` fajlova i posebni browser/cutover smoke runneri. Pokrivaju repository persistence, migration, backup, nutrition planning i research canvas. Nema vidljivog jedinstvenog browser testa za navigaciju kroz sve prikaze, promenu jezika/fokusa, finance refresh lifecycle, Journal ili budući layout. Testovi su **pregledani statički, nisu pokrenuti**: u ovoj okolini `node`/`npm.cmd` nisu dostupni na PATH-u. Nisu pokretani import, restore ni bilo koja operacija koja bi menjala korisnički storage.

## Recommended next steps — plan sa najmanjim rizikom

1. **Pre MVP-a:** ograničiti finance asset refresh na aktivni finance/assets prikaz i zaustaviti interval pri izlasku; dodati jedan fokusirani lifecycle test. Nema promene storage šeme.
2. **Pre MVP-a:** ukloniti prividne Dashboard/Journal podatke sa korisničke putanje. Dashboard vezati za postojeće repository-je sa praznim stanjem; Journal prvo dobija mali dokumentovan data/backup ugovor i tek potom unos/čuvanje. Svaki podkorak zasebno pregledati.
3. **Pre MVP-a:** prebaciti Nutrition favorites kroz odgovarajući repository uz čitanje legacy ključa, idempotentnu migraciju i backup roundtrip test. Sačuvati originalne korisničke podatke dok se parity ne potvrdi.
4. **Tokom narednih bounded MVP izmena:** čuvati identitet editora i ograničavati rerendere u konkretnom prikazu koji se menja; proveriti text-editing event granice i fokus. Ne dirati sve feature-je odjednom.
5. **Nakon stabilizacije MVP-a:** uvesti eksplicitne feature lifecycle i dependency manifest ugovore; meriti lazy loading i prefetch. Prvo izdvojiti čiste finansijske kalkulacije, pa pojedinačne UI tabove, uz postojeće repository-je.
6. **Tek faze 3–4 blueprint-a:** sprovesti stavke iz `THEME_READINESS_BACKLOG.md`, utvrditi stable panel/action ID-jeve, remeasure/cleanup ugovore i settings/backup šemu za izgled. Zatim projektovati Theme Engine, Adapter i Layout Slots bez menjanja domenskih podataka.

## What should be done now

Rešiti A1–A3 i proveriti da MVP korisnički prikazi pokazuju stvarne podatke ili jasno prazno stanje. Svaku promenu proveriti ciljanim testom i backup ugovorom kada dira storage.

## What can wait

A4–A12 rešavati postepeno uz konkretnu promenu zahvaćenog feature-a. React, masovni rewrite i Theme Engine nisu deo ovog rada ni MVP stabilizacije.
