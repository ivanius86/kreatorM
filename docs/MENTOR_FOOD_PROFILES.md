# Mentor food profiles and approved import

## Implementation plan (2026-10-30)

Reuse the existing local capability registry and versioned write pipeline. Add a full-profile reader and a `nutrition.food.create` capability. Keep inventory writes and recipe proposals on their existing paths.

1. Fetch food candidates and full records only from USDA FoodData Central. Gemini interprets/translates names, categories and preparation state; it never provides numeric nutrition values. Require selection of an exact source record.
2. Map all 45 existing nutrient definitions by USDA nutrient IDs and compatible units. Keep missing values null and reported zero as zero. Keep vitamin A RAE separate from IU. Include source metadata and supported measured portions; do not infer allergen absence.
3. Sign the complete source snapshot on the server. Show the same snapshot in the review panel, then verify it before approval executes. Expired or invalid snapshots require a new proposal. Nothing is persisted to the food catalog before approval.
4. Save food, nutrient rows, portions and source in one atomic envelope mutation. Use create-if-absent and exact source identity to prevent duplicate approvals. Keep user data and existing system records intact.
5. Read complete existing profiles locally, including nutrient units, availability, status, source, preparation, portions and dietary/allergen metadata. Generic food questions must not be answered with invented stored data.

Architecture and risk review completed before implementation. Focused checks cover units/nulls, signed proposals, approval, duplicate/concurrent saves, routing and existing inventory behavior.

## Limits

Full profile means every supported field is shown; the source may not report every vitamin or mineral. Unknown values remain unknown. No image import or editing of existing foods is included. Search uses USDA, not arbitrary web pages. `USDA_API_KEY` is optional for development (`DEMO_KEY` has low rate limits); configure a private key for sustained use. An optional `MENTOR_FOOD_SIGNING_KEY` keeps pending signatures valid through server restarts.

## Implemented

- Serbian/English catalog creation commands route to `nutrition.food.create`. Gemini translates the requested food; source candidates must contain the requested search terms, including preparation. The user chooses the exact source record.
- The review panel shows the name, original description, brand when provided, category, preparation, source link, reference basis, dietary/allergen uncertainty, all 45 nutrient fields and verified portion conversions. Numeric values come from one USDA record. A missing value is not filled from another food or generated by Gemini.
- A versioned proposal survives reload. The source snapshot is signed, expires after 24 hours and is verified before saving. Approval words typed in chat never execute the save.
- Food, nutrients, portions and source save together. All food repository mutations now use a fresh atomic envelope, so manual edits and concurrent imports do not overwrite each other. Repeat imports reuse the exact existing source record.
- Complete local profile reads support nutrients, vitamins, minerals, units, statuses, source and portions. Ambiguous food names ask for a selection. The private profile is not sent to the model for these reads.
